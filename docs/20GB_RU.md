# CMP 50HX 20 ГБ

[Главная инструкция](../README.RU.md) · [English](20GB.md)

## Статус

Путь для 20 ГБ поддерживается обновлённым патчем
`patches/cmp50hx/01-cmp50-stockflow.patch`. Он сохраняет путь для исходной
карты 10 ГБ и добавляет динамическую работу с WPR2 для карты большего объёма.

Проверка выполнена 26–27 августа 2026 года на четырёх картах:

```text
PCI device: 10de:1e09
subsystem:  10de:1554
VRAM:       20480 MiB на каждой карте
driver:     NVIDIA Open 610.43.03
ядра:       6.8.0-137-generic и 6.8.0-138-generic
BDF:        01/02:00.0, 03:00.0, 81:00.0, 82:00.0
```

## Почему старый патч не загружал карту

Старый stockflow использовал фиксированные границы WPR2 от карты 10 ГБ. На
проверенной карте 20 ГБ штатный FWSEC создаёт другой диапазон:

```text
WPR high:low = 04ffee00:04ffe000
span         = 00000e00
```

Несовпадение вызывало ошибку NVIDIA Booter `0x8d`; затем GSP-RM исчерпывал
попытки загрузки, и `nvidia-smi` не находил устройства.

Новый патч читает результат успешного штатного FWSEC отдельно для каждого PCI
BDF. Он принимает только размер `0xe00`, сохраняет low/high в состоянии этого
BDF и использует эти значения для повторной попытки, handoff и проверок
готовности GSP. Неожиданный размер или отсутствие сохранённого диапазона
завершает работу безопасно. Временный sentinel WPR-down никогда не сохраняется
как штатное состояние.

### Смешанные системы 10 ГБ и 20 ГБ

Один и тот же модуль может обслуживать карты CMP 50HX на 10 ГБ и 20 ГБ в одной
системе. Сохранённый диапазон WPR2 индексируется адресом bus/device PCI-карты,
а не является общим, поэтому каждая карта сохраняет диапазон собственного
запуска FWSEC. В связанном отчёте проверены четыре карты 20 ГБ; для смешанной
системы всё равно нужна отдельная проверка каждой видимой карты после холодной
загрузки.

## Сборка и установка

Используйте обычный путь CMP 50HX из этого каталога:

```bash
bash ./build.sh --card cmp50hx
sudo ./install.sh --card cmp50hx
```

Для 20 ГБ не нужен отдельный флаг. Установщик видит PCI device `10de:1e09`, а
патч 01 сам использует динамический WPR. После успешной проверки нового модуля
сделайте его постоянным и перезагрузите систему:

```bash
sudo /opt/cmp50hx-unlock/install-initramfs.sh
sudo reboot
```

После загрузки проверьте драйвер и объём памяти:

```bash
nvidia-smi -L
nvidia-smi --query-gpu=pci.device_id,memory.total --format=csv
```

## Проверенный результат

| Проверка | Результат |
| --- | --- |
| Динамический WPR / GSP | `REFWSEC_STOCK_WPR_PASS`, `INPLACE_STOCK_BOOTER_AFTER_UNLOCK_PASS`, `CMP50_GSP_READY` |
| VRAM | Четыре карты, по `20480 MiB` |
| Вычисления | `PASS_CMP50HX_ISSUE_RATE_AND_COUNTS` |
| CUDA / Tensor | `3584 / 448` |
| ReBAR | PCI Region 1 и NVIDIA BAR1 по `16384 MiB` |
| Kernel 138 | Этапы RT-count и ReBAR проверены |
| Kernel 137 Gen2 | Проверено только на эталонном хосте X99 |

## Ограничения

- Проверена плата `10de:1e09` с subsystem `10de:1554`. Другие subsystem не
  входят в этот результат.
- ReBAR и PCIe Gen2 зависят от платы, моста, прошивки и ядра. Результат Gen2
  нельзя считать общим для любого хоста.
- 56 RT-ядер — значение API на стороне хоста. Физические RT-инструкции на
  этом CMP по-прежнему не выполняются.
- Работа idle governor не входила в проверку 20 ГБ.

Если проверка WPR завершается ошибкой, сохраните строки журнала с
`CMP50_WPR_DYNAMIC_V1`, PCI BDF и значениями WPR. Не заменяйте динамическое
определение фиксированным адресом.
